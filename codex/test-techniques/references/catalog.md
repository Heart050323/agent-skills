# テスト技法カタログ

依頼文に使える技法名と、選ぶ場面の目安。分類は発見元の投稿（下記）にならい、説明はISTQBなどの一般的な用語に沿って書き直した。

## A. 範囲と段階（どこまで確かめるか）

| 技法 | 確かめること・選ぶ場面 |
| --- | --- |
| 単体テスト | 関数・クラスなど最小単位の正しさ |
| 結合テスト | 部品同士のつなぎ目（呼び出し、データの受け渡し） |
| E2Eテスト | 利用者の操作を最初から最後まで通す |
| 回帰テスト | 修正後に既存機能が壊れていない |
| スモークテスト | 主要機能が起動・表示できるかを素早く確認 |
| システムテスト | アプリ全体が要件どおりか |
| 受け入れテスト | 使う人の目線で合格条件を満たすか |
| APIテスト | 画面を介さずに応答・状態コード・エラーを確認 |
| コンポーネントテスト | ボタン・フォームなど画面部品を単体で |
| 契約テスト | API提供側と利用側の形（スキーマ）の食い違い |
| サニティテスト | 修正箇所の周辺だけを手早く確認 |
| 機能テスト | 仕様の機能ごとの動作 |
| 探索的テスト | 台本なしで想定外の不具合を探す |
| シナリオテスト | 実際の使われ方の流れ |
| 正常系テスト | 想定どおりの入力と操作 |
| 異常系テスト | 誤入力・通信切れ・権限不足でも落ちない |
| データ移行テスト | 移行前後で件数と中身が一致する |
| モンキーテスト | でたらめな操作・連打で落ちない |
| 確認テスト（再テスト） | 直したバグが再現手順で直っている |
| ブラックボックステスト | 中を見ずに入力と出力だけで確認 |
| ホワイトボックステスト | コードの分岐・経路を見て確認 |
| 運用受け入れテスト | バックアップ・復旧・監視など運用に耐えるか |
| アルファテスト | 公開前に身内で使って不具合を出す |
| ベータテスト | 一部の利用者に先に使ってもらう |
| インストールテスト | 導入・更新・削除の手順で失敗しない |

## B. テスト設計技法（入力と組み合わせの選び方）

| 技法 | 確かめること・選ぶ場面 |
| --- | --- |
| 境界値分析 | 境目の値（最小−1、最小、最大、最大+1） |
| 3値境界値分析 | 境目とその両隣の3点 |
| 同値分割 | 同じ扱いになる入力をまとめ、代表値で少なく試す |
| デシジョンテーブル | 条件と結果の組み合わせの漏れを防ぐ |
| 原因結果グラフ | 条件（原因）と結果の論理関係を整理する |
| 状態遷移テスト | 状態と切り替わり（未ログイン→ログイン中→退会など） |
| Nスイッチ網羅 | 連続した状態遷移の並び |
| ペアワイズ法 | 2因子の組み合わせを網羅しつつ件数を大きく減らす |
| 直交表 | 組み合わせを均等に少なく選ぶ |
| 分類木法 | 入力の種類を木で洗い出す |
| ユースケーステスト | 利用の基本の流れと例外の流れ |
| エラー推測 | 起きやすい誤り（空、0、極端に長い文字列、全角/半角） |
| 命令網羅（C0） | すべての行を一度は実行する |
| 分岐網羅（C1） | すべての分岐の真偽を通す |
| 条件網羅 | 各条件の真と偽 |
| 複合条件網羅 | 条件の全組み合わせ |
| MC/DC | 各条件が単独で結果を左右することを示す |
| パス網羅 | 通り道のパターン |
| CRUDテスト | 作成・読取・更新・削除の各操作 |
| ドメイン分析 | 複数入力の境目をまとめて試す |
| チェックリストテスト | 確認項目の抜けを防ぐ |
| ランダムテスト | 無作為な入力で偏りを防ぐ |
| データフローテスト | 値が定義され使われる流れ |
| シンタックステスト | メール・日付などの書式の正誤 |
| ループテスト | 繰り返しが0回・1回・最大回 |

## C. 非機能（速さ・安全・使いやすさ）

| 技法 | 確かめること・選ぶ場面 |
| --- | --- |
| 負荷テスト | 想定人数で遅くならないか |
| ストレステスト | 限界を超えたときの壊れ方 |
| スパイクテスト | 急な集中アクセス |
| ソークテスト | 長時間稼働での劣化（メモリリークなど） |
| 性能テスト | 応答時間などを数値で測る |
| スケーラビリティテスト | 台数を増やして性能が伸びるか |
| ボリュームテスト | 大量データでの動作 |
| キャパシティテスト | 何人・何件まで耐えるか |
| 脆弱性診断 | 入力欄・認証などの弱点 |
| ペネトレーションテスト | 攻撃者の目線で侵入を試す（許可された環境のみ） |
| ファジング | 想定外の入力を大量に与えて落ちる所を探す |
| 静的解析 | 実行せずにコードの危ない書き方を探す |
| クロスブラウザテスト | 主要ブラウザーで同じに動く |
| 互換性テスト | OS・機種・バージョンの違い |
| 実機テスト | 本物の端末での動作 |
| アクセシビリティテスト | WCAGに沿って誰でも使えるか |
| コントラスト比確認 | 文字と背景の比（本文4.5:1以上が目安） |
| ユーザビリティテスト | 初めての人が迷う所 |
| 国際化テスト | 言語・地域・時差の切り替え |
| ローカライズテスト | 翻訳後の文字あふれ・表記 |
| 並行性テスト | 同時操作でデータが壊れない |
| カオスエンジニアリング | 一部を止めても動き続けるか |
| 障害注入テスト | 通信切れ・遅延を意図的に起こす |
| リカバリテスト | 異常終了後に復旧できるか |
| フェイルオーバーテスト | 予備系に切り替わるか |

## D. 自動テストの型と道具

| 技法 | 使いどころ |
| --- | --- |
| スナップショットテスト | 出力の意図しない変化に気づく |
| ビジュアル回帰テスト | 画面の見た目の差分を画像で比較 |
| プロパティベーステスト | 性質を決めて大量の自動入力で反例を探す |
| メタモルフィックテスト | 正解が不明でも「入力を変えたときの関係」で確かめる |
| ミューテーションテスト | コードをわざと壊してテストが検出できるか |
| カバレッジ計測 | テストが通った範囲と未テスト箇所 |
| テスト駆動開発 | 先に失敗するテストを書いてから実装 |
| 振る舞い駆動開発 | Given-When-Thenで振る舞いを書く |
| 特性テスト | 直す前の現在の挙動を記録して守る |
| パラメータ化テスト | 1つのテストで多くの値を試す |
| テーブル駆動テスト | 入力と期待値を表で並べる |
| AAAパターン | 準備・実行・確認の3段に分けて書く |
| テストフィクスチャ | 毎回同じ準備データ |
| ティアダウン | テスト後の後片付けで影響を残さない |
| モック | 呼ばれ方まで確かめる代役 |
| スタブ | 決まった答えを返す代役 |
| フェイク | 簡易な本物の代わり（メモリ上のDBなど） |
| スパイ | 呼ばれた記録を後で確かめる |
| ダミー | 使わない引数を埋める代役 |
| ページオブジェクト | 画面変更に強いE2Eの書き方 |
| ヘッドレスブラウザ | 画面を出さずにE2Eを自動実行 |
| テストピラミッド | 単体・結合・E2Eの数の配分 |
| 並列テスト | テストを同時に流して短縮 |
| 継続的インテグレーション | 変更のたびに自動でテスト |
| フレーキーテスト対策 | たまに落ちるテストの原因（時刻、順序、待ち時間）を直す |
