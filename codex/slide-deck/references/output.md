# 出力形式を選ぶ

構成案が決まってから選ぶ。既存のテンプレート、社内の形式、プロジェクトの道具があればそれを優先する。

| 納品・使い方 | 第一候補 | 注意 |
| --- | --- | --- |
| 受け取った人がPowerPointで直す | 編集可能なPPTX（文字・図形をPPTXの要素として作る） | Claudeでpptx系スキルが使えればそれを使う。なければpython-pptx等。画像を貼っただけのPPTXを「編集可能」と言わない |
| PDFで配る・印刷する、文章から手早く作る | Marp（[marp.md](marp.md)） | `--pptx` は各ページが画像のPPTX。編集可能版は実験機能で制約がある |
| ブラウザーで発表する、コードを1行ずつ見せる、動きで順番を見せる | reveal.js（[revealjs.md](revealjs.md)） | 動きは順番を伝えるときだけ。PDF化は印刷用の表示から |
| 既存のHTML/CSSの仕組みがある | その仕組み | 書き出しの方法をプロジェクトの手順に合わせる |

## どの形式でも守ること

- 16:9（1920×1080相当）を基準にし、指定があれば従う。寸法を変えるときは比例で換算する。
- 色・書体・余白は先に決めた「色の役割」と画風から、テーマ（CSSの変数やスライドマスター）に1か所でまとめて定義する。ページごとに色を直書きしない。
- 日本語の書体はプロジェクト指定を優先。なければmacOSならヒラギノ角ゴシック、配布先で同じ表示が必要ならNoto Sans JPなど、書き出す環境と受け取る環境の両方で使えるものにする。
- 既定テーマの作例（グラデーション背景、暗い背景に明るい文字、中央寄せの大見出し）をそのまま使わない。画風の指定がなければ、白地・濃いグレーの文字・アクセント1色から始める。
- 編集用のソース（.md / .html / 生成スクリプト）を成果物と一緒に残す。
- 新しいCLIやパッケージを入れる前に、手元に入っているか確かめる。入れる場合は名前と版を伝える。

## 点検のための画像書き出し

SKILL.mdの「5. 見て直す」で使う。実際に渡す形式から作った画像で確かめる。

- Marp: `marp --images png deck.md`（各ページがPNGになる）
- reveal.js: 印刷用表示（`?print-pdf`）からPDFを作り、PDFをPNGに変換する。またはヘッドレスブラウザーで各ページを撮る。
- PPTX: LibreOfficeがあれば `soffice --headless --convert-to pdf deck.pptx` でPDFにし、PNGへ。PowerPointで開ける環境なら実物でも確かめる。
- PDF→PNG: `pdftoppm -png -r 80 deck.pdf page`（poppler）や、手元のPDFライブラリ。

一覧で並べて見るときは、縮小画像を1枚に並べる（ImageMagickの`montage`など）と、色や強さのばらつきが分かりやすい。
