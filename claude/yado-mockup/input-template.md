# 入力ブロック書式

`/yado-mockup` のあとに、このブロックを埋めて貼る。分からない項目は消さずに「未確認」と書く（エージェントは空欄を推測で埋めない）。

```text
## 対象宿の一次情報
- 宿名:
- 所在地: [市町村・都道府県]
- 運営者の背景: [移住歴、前職、地域との関係]
- 建物・滞在の特徴: [古民家の年代、DIY、部屋数、一棟貸し/家主滞在、景観]
- 体験・地域資源: [農、食、海、山、アート、サウナ、文化、移住体験等]
- 想定客: [例: 都市部の30〜50代カップル、家族、ワーケーション、移住検討者]
- 現行チャネル: [例: Airbnbのみ / Airbnbと小規模な予約ページ]
- 公式SNS: [Instagram/Facebookの公式アカウントURL。公式と確認できなければ「未確認」]
- SNS表示候補: [投稿URL、投稿日、確認日。複数可。未確認なら「未確認」]
- 外部レビュー: [媒体名、対象宿ページURL、評価、件数、カテゴリ別評価、要約候補、確認日。未確認なら「未確認」]
- 公開住所: [郵便番号を含む住所。公開可否も記載]
- 交通・駐車場: [最寄駅、徒歩/車の所要時間、無料/有料、台数。未確認は推測しない]
- 地図: [Google Maps検索URL、Embed APIキーの有無、公開位置を正確/周辺表示のどちらにするか]
- 宿情報台帳: [定員、寝室、寝具、浴室、設備、規則、チェックイン/アウト、許可番号、ホスト、周辺施設など、OTA公開情報を項目別に列挙]
- 表示言語: [基本: ja / en / zh-CN / zh-TW / ko + 対象地域の主要言語1つ以上]
- 現地対応言語: [運営者が実際に応対できる言語。サイト表示言語と分ける]
- 確認済みの外部導線: [問い合わせURL、予約URL。未確認なら「未確認」]
- このサイトで解くべき仮説: [例: Airbnbの設備一覧だけでは、農・食・移住体験の価値が伝わらない]
- 使用する実写素材: [例: assets/reference/hero.jpg ほか。無ければ「なし」]
- 画像出所台帳: [assets/reference/asset-manifest.json のパス。無ければ「なし」]

# 宿の特徴やテイスト（人間の方針）
[人間（自分たちや宿の人）にしか見いだせないアピールポイント、推したい空気感、
 避けたい表現、参考にしたい方向性を自由記述。ここが3案すべての最優先指示になる]
```
