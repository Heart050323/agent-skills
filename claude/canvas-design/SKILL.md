# Canvas Design

1枚の静止画を「考え方（デザインフィロソフィー）→ 画面」の2段階で作る。AnthropicのCanvas Designスキルを、日本語の告知物にも使えるよう絞った改変版。[出典と変更点](references/sources.md)

## まず用途を決める

依頼から、どちらの型かを決める。曖昧なら告知型として扱う。

- **アート型**: 展示用、作品、抽象的なキービジュアル、イベントのムード画像。文字は最小限で、図形・色・構図で語る。原版の進め方そのもの。
- **告知型**: セミナー、セール、新メニュー、求人、旅行キャンペーンなど、見た人に情報を伝えて行動してもらうもの。読む順番（何の告知か → 日時・価格などの要点 → 申込方法）が見た目より優先される。

ブランド資料、ロゴ、写真、指定色、既存のトンマナがあれば、それを最優先の前提にする。事実（日時、価格、会場、実績の数字、人物の言葉）は依頼にあるものだけを使い、作らない。足りない情報は空欄の枠か「要確認」と明示した仮テキストにする。

## 1. デザインの考え方を書く（.md）

画面を作る前に、短い文章で方針を決めてファイルに保存する。

- 方針に1〜2語の名前を付ける（例: 「静かな幾何」「紙と墨」「色で区切る」）。
- 3〜5段落で、空間と形、色と素材、大きさとリズム、構図と重心、視覚の優先順位を書く。同じ論点を繰り返さない。
- 告知型では「最初の1秒で何が読めるか」「2番目に目が行く要素」「最後に読む要素」を1行ずつ書く。
- 毎回同じになりやすい既定の構図（中央に大きな文字＋ぼかした背景、全面グラデーション、文字と背景の低コントラスト）は、依頼が求めていない限り使わない。

## 2. 題材を画面に溶け込ませる

依頼の題材から、構図や色に織り込む具体的な手がかり（素材、道具、地形、季節、業界の慣習的な形）を1つ選ぶ。アート型では説明せず、気づく人だけが気づく程度に留める。告知型では写真・図・大きな数字など、内容を最も早く伝える要素を主役にする（例: セールなら割引率、新メニューなら料理写真、セミナーなら日時と演題）。

## 3. キャンバスを作る（.png / .pdf）

- 実装手段は環境に合わせる。HTML/CSS→ヘッドレスブラウザーで画像化、Python（Pillow、reportlab、matplotlib）、SVGなど、手元で動くものを使う。新しい実行ファイルを外部から取得して実行しない。
- 文字は内容に合った書体を選ぶ。日本語はmacOSのヒラギノ（角ゴ・明朝）や、プロジェクトに同梱・ライセンス確認済みのフォント（Noto Sans JP / Noto Serif JPなど）を使う。フォントを新たにダウンロードする場合は配布元とライセンスを確認し、ユーザーに伝える。
- 余白を十分に取り、すべての要素をキャンバス内に収める。文字同士・文字と図形の重なり、はみ出し、背景に溶けて読めない文字は作らない（本文相当は背景とのコントラスト比4.5:1以上を目安）。
- 限られた色数で、意図のある配色にする。告知型では情報の階層を大きさ・太さ・位置で明確にし、要点は離れた位置からでも読める大きさにする。
- 出力サイズは用途に合わせる（例: A4/A3印刷はPDFで実寸＋塗り足しの要否を確認、SNSはPNGで各サービスの推奨比率）。指定がなければ用途を一言添えて決める。

## 4. 仕上げの見直し

完成した画像を実際に開いて確認する。足すより削る方向で整える。新しい図形や効果を足したくなったら、まず「今ある要素をより揃えられないか」を考える。確認項目: 文字の誤字・脱字、重なりとはみ出し、余白の均整、読む順番、事実の正確さ、縮小表示（サムネイル）での判読性。

## 複数枚

シリーズを頼まれたら、同じ考え方を共有しつつ構図は1枚ずつ変える。1つのPDFにまとめるか、連番PNGで出す。

## 出力

成果物（画像/PDF）と、使った「デザインの考え方」の.mdをプロジェクト内の指定場所（なければ作業ディレクトリ）に保存し、パスを伝える。
